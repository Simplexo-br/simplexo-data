# Commercial Model Baseline

Primitivas: plano -> entitlements -> quotas -> eventos medidos -> ledger imutável. Crédito é unidade comercial, não autorização. Preview, 360, enrichment, export, API e IA podem ter regras distintas exibidas antes do consumo.

Tiers candidatos: discovery/free, team, business, enterprise/API. Preço, rollover, reembolso, tributos e fair use não estão aprovados. Idempotency evita cobrança dupla e o cliente vê uso/auditoria. Reusar product/sale/portal/website Odoo; provisioning idempotente e reversível.
